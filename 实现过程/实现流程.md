## 第二件事：先跑 Mock 模式

为了让你作为小白可以先把整条链跑通，我专门做了：

```env
YAGENT_LLM_MODE=mock
```

所以第一遍**不需要 DeepSeek API Key**。

先复制：

```bat
copy .env.example .env
```

然后直接：

```bat
docker compose -f infra/docker-compose.yml --env-file .env up --build
```

它会启动：

```text

Redis            6379
MinIO            9000/9001

YAgent Platform  8080
YAgent Runtime   3000
Node Runner      8090
```

## 然后再切真实 DeepSeek

等 Mock 跑通以后修改 `.env`：

```env
YAGENT_LLM_MODE=deepseek

DEEPSEEK_API_KEY=你的Key

DEEPSEEK_BASE_URL=https://api.deepseek.com

DEEPSEEK_MODEL=deepseek-chat
```

重新启动：

```bat
docker compose -f infra/docker-compose.yml --env-file .env down
docker compose -f infra/docker-compose.yml --env-file .env up --build
```

此时：

```text
MockAgentRuntimeAdapter
```

就会替换成：

```text
DeepSeekAgentRuntimeAdapter
```

而：

```text
CapabilityResolver
ToolManager
PermissionClient
ToolMaterializer
ToolRegistry
Sandbox
Audit
```

完全不用改。

这也是为什么项目里专门有：

```text
packages/yagent-runtime-core
packages/yagent-runtime-adapter-deepseek
```

两层。

有一点需要说明：我已经把工程、SQL、预制 `package.ytool` 和对应 SHA256 都生成好了，但当前执行环境无法访问 npm/Maven 网络仓库，所以这里**没有实际完成远程依赖下载后的完整编译测试**。代码结构和整条调用链已经落地，你在自己的 Windows/WSL 网络环境执行 `docker compose ... up --build` 后，如果出现第一个编译错误，把完整错误发给我，我们就从**第一个错误开始逐个修到整个项目真正跑通**。

你现在最适合做的就是：**下载 ZIP → 解压 → `.env` → Docker 启动 → 先打 `/runtime/health`。**

运行可能踩的坑
这一路踩过的坑（小结）
```
问题	根因
Docker build ECONNRESET	npm 源不通 → 换 npmmirror.com
TS2339 Property 'function' does not exist	OpenAI SDK v6 联合类型 → 类型收窄
MySQL 端口冲突	本机 MySQL 占 3306 → 映射改 13306
MYSQL_USER=root 拒绝启动	MySQL 8.4 不允许 root 当普通用户
.env 不生效	Compose 只读 compose 同目录的 .env
node-runner ERR_MODULE_NOT_FOUND: express	pnpm 符号链接被 WORKDIR /app 打断
YAGENT_LLM_MODE=deepseek	只认 real / mock
SHA256 mismatch	DB 里存的是占位符/错值
Cannot find @yagent/tool-sdk-node	工具包没自带依赖 → 打包时打进 zip
```
